## Сценарий демо D2

1. Запустить реальный API с PostgreSQL и веб-клиент. Открыть два независимых профиля браузера.
2. Зарегистрировать аккаунты A и Б. Войти, найти Б по публичному ID и создать диалог.
3. На A создать ключ. Передать его вручную вне чата и ввести на Б. Проверить, что ключ отсутствует в запросах.
4. Отправить текст A → Б и Б → A. В интерфейсе виден исходный текст, в запросе отправки — пакет с `iv` и `ct`. Повторить тот же пакет и проверить, что в истории одна запись.
5. В сборке с MSG-38 прикрепить фото с подписью и короткое видео. На Б открыть вложения и скачать их. Сверить байты с оригиналами. В запросах имя и подпись передаются внутри зашифрованных метаданных.

## Удаление и восстановление связи

Для каждого ряда создать отдельное зашифрованное сообщение, а для проверки файлов добавить вложение. Сверять рабочие копии через историю и `POST .../messages/sync` после возвращения сети. В веб-клиенте обновление может дождаться REST-опроса. Серверный SignalR проверяется отдельно.

| Действие A | Состояние Б | Ожидаемое после удаления и сверки |
| --- | --- | --- |
| Удалить у себя | Онлайн | A теряет свою копию. Б сохраняет сообщение и доступ к файлу. |
| Удалить у себя | Офлайн, затем reconnect | После сверки у Б остаётся своя копия. У A удалённая копия не появляется. |
| Удалить у обоих | Онлайн | У обоих исчезают сообщение и доступ к файлу. |
| Удалить у обоих | Офлайн, затем reconnect | После сверки на Б сообщение исчезает. Повтор старой отправки не восстанавливает удалённые копии. |

Связь с требованиями — FR-11 и FR-12. Связь с негативными проверками — TC-12, TC-13, TC-25-N4. Для сторонней сессии операции над чужим диалогом, метаданными вложения и его содержимым должны вернуть 404.

## Граничные проверки вложений

Для FR-13…15 и TC-25 использовать актуальный фронтенд и API из MSG-38. Автотесты фронтенда находятся в `tests/media.test.js`.

| Данные | Ожидаемый результат |
| --- | --- |
| 0 байт | Пустой файл отклоняется. |
| 25 000 000 байт | Шифрование и расшифровка успешны. Длина тела загрузки равна длине исходного файла. |
| 25 000 001 байт | Клиент отклоняет файл. Запрос сверх серверного лимита получает 413. |
| Изменён GCM-тег файла или повреждён пакет метаданных | Клиент сообщает об ошибке и не показывает содержимое. |
